## Common acceptance gate

The Windows jobs used the same synthetic Matter surface and shared UI Automation probe. The behavioural gate required:

- a real top-level Windows UIA element;
- at least eight accessibility descendants;
- at least five buttons and five keyboard-focusable descendants;
- an Edit control named `Search this Matter`;
- Windows UIA `ValuePattern` on that search control;
- incremental `w` → `wa` → `war` filtering without pressing Enter;
- clearing search restores the hidden timeline action;
- an accessible transcript control named `AI conversation transcript` exposing `TextPattern` or `ValuePattern`;
- source-like transcript text retrievable through that accessibility pattern;
- developer/build paths removed before consumer launch;
- no runnable executable uploaded as a workflow artifact.

### Known limitation

Avalonia 12.1.2 analyzers report that the .NET 8.0.424 SDK compiler is older than the compiler version against which some analyzer assemblies were built. The product binary still compiled and passed the consumer/UIA gate. A later isolated build-tool qualification should compare/pin a newer FOSS .NET SDK rather than silently changing this build input during the framework comparison.

## Fyne 2.8.1 — HOLD / native UIA not qualified

Pinned framework: Fyne v2.8.1, BSD-3-Clause.  
Exact built executable:

- SHA-256: `31f96d340506ac1f94e4b7ef4a4cf2c72c90251cd856fc53ce1d592a1c8b3043`;
- bytes: `24,154,624`.

Build succeeded with the `accessibility` tag, but consumer launch failed before a Windows window was created:

`APIUnavailable: WGL: The driver does not appear to support OpenGL`

The current Fyne repository itself avoids GLFW native GUI tests on GitHub `windows-latest` by using the `no_glfw` tag, so hosted GitHub Windows is not a fair native UIA environment for Fyne. Do not call this an accessibility failure.

Separate source inspection remains adverse:

- current Windows accessibility provider returns no UIA control-pattern provider;
- code search found no `ValuePattern` implementation;
- v2.8.1 `widget.Entry` does not declare the new `fyne.Accessible` interface.

Therefore Fyne remains **HOLD** unless a real Windows machine with working OpenGL can prove the required search/transcript accessibility behaviour. It is not the preferred next shell while Avalonia has already passed the same behavioural gate.
