# V39 M1.18 — final controlled AI-turn orchestrator

**Status:** bounded source implementation on a fresh current-main development branch; not integrated into ECO UI, workspace, evidence, Ask ECO or a real model runtime.

## Purpose

M1.18 provides one transaction boundary for a complete local-AI turn. It coordinates existing or future implementations through narrow interfaces rather than recreating their internal responsibilities.

The package is `internal/runtime/turnorchestrator`.

## Continuity truth

The earlier isolated V39 source line was not committed to Git. Its M1.12 manifests, receipts and validation records survive, but the exact sealed source ZIP and later M1.13–M1.17C source objects are not retrievable through the currently available project stores.

M1.18 is therefore **not** described as a byte-continuation of M1.12 or M1.17C. It is a fresh in-repository consolidation based on the surviving contracts and control records. Historical source hashes remain historical evidence; they are not claimed as parents of this branch.

This is the final new isolated engine. Later work must implement adapters and application journeys rather than create another orchestration engine.

## Owned responsibility

M1.18 owns only turn sequencing and the final acceptance boundary:

1. validate a bounded request;
2. ask an injected compiler for an opaque compiled context;
3. ask an injected router for an exact model/runtime/adapter route;
4. obtain an injected supervisor admission lease;
5. invoke an injected runner with a generation-bound run identity;
6. accept only ordered, correctly bound, bounded stream chunks;
7. release the lease exactly once;
8. submit completed generated bytes to an injected verifier;
9. expose accepted text only after verification and cleanup;
10. otherwise request a deterministic fallback or return a controlled cancellation/failure;
11. erase all orchestrator-owned prompt, runtime, generated, verification and verifier-output buffers and zero fallback byte buffers after copying accepted fallback text;
12. return a bounded receipt containing identities, counts, outcome and reason codes but no request, prompt, generated or output text.

## Explicit non-ownership

The package does not:

- retrieve evidence;
- compile prompts itself;
- select or verify model files itself;
- launch, sandbox, supervise or kill a worker itself;
- implement IPC itself;
- persist memory, plans, casework, conversations or workspace state;
- decide whether generated claims are correct;
- perform application actions;
- render UI;
- load Qwen, llama.cpp or another model/runtime;
- provide legal, medical, forensic or professional conclusions.

Those responsibilities remain behind injected contracts and later application adapters.

## Fail-closed controls

- invalid request, context, route, generation and verifier results are rejected;
- partial compiler prompts returned alongside errors or invalid metadata are transferred immediately into owned cleanup state;
- model, runtime and adapter identities must be lowercase SHA-256 values;
- every admitted turn receives a fresh cryptographically random 128-bit run identity;
- stream chunks must carry the exact turn/run identity and strictly increasing sequence;
- per-chunk, total-output, request, prompt and timeout limits are enforced;
- cancellation and timeout return no generated or fallback text;
- late chunks are rejected after stream closure and cannot enter verification;
- generated bytes are never returned as accepted text without verifier acceptance;
- deterministic fallback is rejected unless explicitly marked deterministic and structurally valid;
- dependency panics, including clock panics, become bounded reason codes without exposing panic text;
- only allowlisted non-content generation finish reasons may enter receipts;
- lease-release or erasure failure suppresses all output;
- cleanup contexts carry their own bounded deadlines;
- the receipt contains sizes and opaque identities, not content fingerprints that could leak short user text through dictionary attacks.

## Integration boundary

The application must supply adapters for:

- context compilation;
- model/runtime routing;
- worker admission and lease release;
- streamed generation;
- deterministic answer verification;
- deterministic fallback;
- sensitive-buffer erasure.

The first integration must remain synthetic and must not connect real evidence or a public executable.

## Remaining limitations

- no historical M1.12–M1.17 source restoration is claimed;
- no current application package imports this package;
- no real worker, process sandbox, IPC channel, model or runtime was exercised;
- a dependency that ignores context cancellation can still block its own call; concrete adapters must satisfy the cancellation contract and use OS process termination where required;
- receipt persistence, encryption and diagnostic-export filtering remain application responsibilities;
- no Acer latency, memory, thermal, power, endurance or crash-recovery evidence exists;
- no user-visible product progress is created by this source milestone alone;
- request text and final accepted text remain Go strings at the public API boundary and cannot be overwritten in place; adapters must avoid retaining unnecessary copies.
